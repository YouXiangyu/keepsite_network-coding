# 生活纪念品数字收藏：当前产品规格

版本：0.14。更新日期：2026-10-20，Asia/Shanghai。

本文只写当前有效规则，每条注明决定编号。执行顺序与工作包见[开发计划](开发计划.md)。旧版全文与访谈原话见 [history](history/项目定义与决策主文档-v0.13.md)，原始资料见 [sources](sources/)。两者只读；其中的内容未写入本文的，不构成当前需求。

## 1 产品定义与边界

- 一张图片对应一件收藏（D-027）。票根、标签和生活照片保存为可回顾的数字纪念品；首页是以图片和立体效果为主的收藏墙（D-028）。
- 客户端：响应式 Web App，只要求在线使用（D-004、D-041）；Kotlin 原生 Android App，本地优先、可离线、负责近场分享（D-048）。
- 服务端：FastAPI + SQLite 保存账号业务数据，Cognito 管理身份，私有 S3 保存图片与模型，运行于 AWS EC2（D-045）。
- 分享是复制与推荐，不转移所有权；不做票务交易、验票或数字资产（开题 A §2.2、§5.3）。
- 运行阶段不接受付费 API（D-025）。识别语言为简体中文与英文字母（D-014）。

## 3 功能规格

### 3.1 账号与会话

- 未登录只能使用登录、注册、邮箱验证与找回密码（D-042）。支持 Google 一键登录、邮箱密码注册（验证码确认）与邮件重置密码（D-030、D-032）。
- 身份、初始化与授权由后端决定。每个账号的收藏、分享、资料与任务独立；跨账号读取图片、模型或任务一律拒绝（D-043）。
- Web 使用服务器签发的 HttpOnly 会话 Cookie 与 CSRF 令牌；浏览器不保存身份提供方令牌。
- Android 的邮箱登录、注册验证与找回密码走与 Web 相同的后端接口；Google 登录经 Custom Tabs 打开 Cognito 托管页并使用 PKCE，不嵌入 WebView。后端为 App 签发非 Cookie 的会话凭据，App 用系统 Keystore 加密保存（D-048）。
- 退出不删除本地或云端数据，但退出后不得向未登录状态或其他账号展示（D-031）。Android 凭据过期时本地功能继续，云端操作等待重新登录（D-029）。

### 3.2 收藏与来源

- 字段：标题、展示分类（电影、旅行、日常、展览）、标签、备注、日期、识别字段及其来源；`art` 占位插画字段只用于展示降级。
- 新建只要求图片；标题、日期可留空，由识别填写（D-060）。识别后仍为空时界面显示“未命名”，缺日期的收藏按创建时间排序。
- 来源只有“我的”与“朋友推荐”（D-038）。用户修改优先于任何自动结果（D-016、D-020）。
- 删除同步到本人各端，旧设备上的过期修改不能使记录复活；朋友已收的副本独立（D-034）。

### 3.3 生成触发与浮雕

- 触发（D-007、D-051）：新建收藏；更换原图；修改关键识别字段——电影票的片名或放映日期、交通票的出发或到达城市（站点）或日期，分别重新取海报或重新生成徽章。
- 不触发：标题、分类、标签、备注与 `art` 占位插画的修改。
- 浮雕输入：电影票用海报，无可信匹配时用票的照片；交通票用徽章，缺出发或到达城市时用票的照片；其他类型用原图。
- 照片与海报浮雕沿用 AnyImage 深度推理（D-002）；徽章按图层高度生成，不做深度估计。三者都导出 GLB，使用同一查看规则。
- 生成服务不可用时先保存二维收藏，恢复后自动补生成（D-009）；旧任务结果不能覆盖新输入，也不能复活已删除的记录。
- 查看（D-040、D-037）：总偏转不超过 40°，指针或触点所在的边、角向下按压；卡片晃动或悬停效果不等于模型已生成。模型是 2.5D 浮雕，不是 360° 重建。

### 3.4 识别与自动分类

- 收藏先保存，服务端随后在现有串行生成 worker 中执行 OCR，不与浮雕推理并发；按文字关键词规则判断类型并提取字段，不用 AI 模型或付费 API（D-050、D-060、D-017）。界面在识别期间显示“识别中”。
- 用户已填写的字段优先；识别只填空字段，并记录每个字段的来源；无可靠结果留空（D-016、D-018）。
- 不提取、不保存乘客姓名与证件号；OCR 全文不持久化、不写日志（D-050）。

| 类型 | 提取字段 | 标题为空时填写 | 展示分类 | 浮雕输入 |
| --- | --- | --- | --- | --- |
| 电影票 | 片名、影院、影厅与座位、放映时间 | 片名 | 电影 | 海报（3.6） |
| 交通票（高铁、火车、飞机、汽车） | 出发与到达的站点或城市、车次或航班号、日期 | “出发城市—到达城市” | 旅行 | 双城徽章（3.7） |
| 饮品标签 | 名称 | 名称 | 日常 | 原图 |
| 购物小票 | 店名、日期 | 店名 | 日常 | 原图 |
| 其他（景区与展览门票、食物、无文字或认不出类型的图片） | 无 | 不填 | 日常 | 原图 |

- 展示分类只在用户未手选时自动填写；用户手选优先（D-058）。日期为空时用识别出的放映日期、乘车日期或小票日期填写。
- Android 离线 OCR 使用 ML Kit 中文捆绑模型，不依赖 Play 服务；只做文字与少量字段，不做自动分类；联网后以服务端结果为准，用户填写仍优先（D-003、D-012、D-017）。

### 3.5 标签匹配

- 标签为空的收藏在标题首次确定时匹配一次：新建时已有标题就立即匹配，标题由识别填写时在识别结果发布时匹配。用标题关键词匹配全部用户的手填记录，取命中记录中占比最高的一个标签；无命中不设标签（D-019、D-049）。
- 只统计用户自己新建并手填标签的记录；初始模板复制的记录（即使之后被编辑）与来源为朋友推荐的收藏都不计入（D-059）。
- 修改只影响本人该条；已保存的收藏不随之改变（D-020、D-021）。

### 3.6 电影海报

- 按片名检索海报：TMDB 为主，维基百科备选（D-052）。TMDB API Key 由用户本人注册后写入服务器环境文件；缺少 Key 时直接使用维基百科。
- 同名多部时选上映日期最接近放映时间的一部；无可信匹配时用票的照片（D-018）。
- 海报作为收藏封面与浮雕输入；票的照片保留为原图（D-027）。
- 海报按影片 ID 缓存为共享不可变文件，存于现有私有 S3 并经授权读取；页面标注数据来源，并注明仅限小范围非商用测试。
- 修改片名或放映日期后重新检索并重新生成。

### 3.7 徽章

- 适用（D-053、D-058）：只有交通票按出发、到达两城生成；缺任一城市时暂不生成，用户补填后按 3.3 生成。景区与展览门票、饮品标签、购物小票与其他照片不生成徽章。
- 服务器从城市元素素材库中随机抽取元素组合，并抽取稀有度：普通、稀有、史诗、传说。默认概率与各档视觉表现见开发计划，属于可调整的默认值。
- 抽取结果持久化，重新打开不变；用户修正城市、站点或日期后按修正值重新抽取，初期不做防刷。
- 素材库由用户在开发阶段用 GPT 生图批量生成并审核，形成带版本的静态素材库，包含站名、机场到城市的映射表。运行时只组合素材，不调用生图接口（D-025）。素材库未覆盖的城市使用通用徽章（城市名加配色图案）。
- 徽章按图层高度生成浮雕 GLB，复用现有查看器与 40° 规则。
- “我的”页提供徽章墙，显示已收集的城市元素与各稀有度数量。

### 3.8 节日特效

- 按票面日期判断节日：元旦、春节、元宵、清明、劳动节、端午、七夕、中秋、国庆、圣诞。农历节日自动换算，清明按节气（D-054）。
- 有法定假期的节日（元旦、春节、清明、劳动节、端午、中秋、国庆）在整段法定假期内生效，假期按固定版本的历年国务院安排数据判断；数据未覆盖的年份只算节日当天。元宵、七夕、圣诞只算当天。日期同时落在两个节日时，节日当天优先，否则按假期数据标注的节日。
- 电影海报与徽章都加节日特效：素材库中的静态装饰层，不做查看器动画。海报在 AnyImage 浮雕外加一圈固定高度的节日边框，不参与深度估计；徽章把节日元素作为一个图层按设定高度加入。

### 3.9 同步

- 服务器为 App 提供同步接口：按游标增量拉取变化，按操作 ID 幂等上传离线修改，删除写墓碑，检测版本冲突（D-047）。
- 覆盖收藏与个人资料；近场收到的分享在近场分享阶段加入。生成完成与识别结果发布也计入变化。
- 冲突按字段处理：每次上传只带改动的字段，服务器按收到的先后应用，同一字段后到的覆盖先到的，不同字段都保留（D-061）。不做冲突选择界面。
- 删除是最终的：收藏删除后，之后才到达的修改返回“已删除”，不恢复该收藏（D-061、D-034）。
- 不以手机时钟判断先后，不上传整个数据库。Web 继续使用现有在线接口，并能读到 App 同步上来的数据。

### 3.10 Android App

- Kotlin 与 Jetpack Compose；Room 保存本地数据，WorkManager 执行后台同步，前台服务承担近场传输；支持拍照与相册导入（D-048）。
- 本地优先：首次登录后，离线可拍照、保存、编辑与浏览，联网后同步（D-029）。
- 本地数据按账号隔离，换号不串数据。
- 浮雕查看器原生实现，加载同一 GLB，遵守 3.3 的查看规则。
- 页面结构与视觉按 V1–V5（D-035）。离线 OCR 见 3.4。

### 3.11 近场分享

- 两台 Android 在无互联网时通过 Wi-Fi Direct 建立连接，用 TCP 传输。发送方选择内容；接收方确认或拒绝；支持取消、完整性校验、断点续传、去重与可靠导入；先显示信息与缩略图，再传大文件。
- 只维护一套版本化协议：控制消息使用带长度前缀的 JSON，文件使用二进制帧；限制包大小、文件数量、类型与路径。
- TCP 链路使用 TLS；配对时用二维码或短码核对对端公钥指纹，不能只凭设备名，也不能跳过证书校验。
- 接收方得到独立副本，来源为朋友推荐；原作者之后修改或删除不影响该副本。收到的分享随同步上传，Web 分享页展示这些记录（D-055）。
- 细则（D-062）：元数据、封面图与 GLB 到齐即视为接收成功；原票照片可能含姓名与证件号，默认不发送，由发送者勾选；同一快照重复接收不新增；他人转发视为新来源；原作者的新版本作为新包；取消后的临时文件 24 小时后清理；续传要求对端身份与包一致，无需再次确认；删除后允许主动重新接收。
- 最终验收需要两台真机，由用户执行（D-057）。

### 3.12 本地副本、删除与缓存

- Android 为每件收藏保留完整副本：原图、模型、必要纹理以及海报、徽章等派生资产（D-033）。未同步的内容必须保留到同步完成。
- 清理缓存只删除临时与中间文件；删除收藏同步到本人各端；朋友的副本不受影响（D-034）。
- 素材未下载完整时显示真实状态；空间不足时报告未完成，不冒充完整。

### 3.13 探索与分享页

- Web 不做在线分享与社区发布。分享页只展示手机近场收到并同步上来的记录；现有初始示例保留，并作为示例标明（D-055）。
- 探索保持示例与预置内容；新上传默认私有（D-036、D-055）。

### 3.14 视觉与交互

- 浅色中性背景、醒目的深色标题、图片主导的卡片（D-035、D-041）。Web 使用响应式布局与原生表单，不渲染手机外壳；Android 按 V1–V5 与五位置底栏。
- 键盘焦点可见，触控目标足够大，尊重减少动态效果设置；加载、失败与生成状态清楚可见。

## 4 非目标

- 在线分享、社区发布与真实热度推荐（D-055）。
- 浮雕参数实验接入生产（D-056）。
- Meshy 与任何付费 API（D-006、D-025）。
- iOS、跨公网 NAT 穿透、多人 P2P。
- 稀有度防刷（D-053）；景区与展览门票徽章（D-058）；同步冲突选择界面（D-061）；打卡与体验状态（D-038）。
- 多图或视频收藏（D-027）；Web 离线使用（D-004）。
- 票务交易、验票、数字资产所有权；360° 完整物体重建与骨骼动画。

## 5 运行环境

- AWS 东京 EC2 `t3.small`（2 GB），单应用进程、单生成 worker；Nginx 提供 HTTPS；Cognito 管理身份；私有 S3 保存文件（D-045）。实例、路径、费用与启停规则见[项目运行信息](../.agents/skills/memoverse-delivery/references/project-context.md)，本文不重复。
- 每次开机 58 分钟后自动正常关机；部署、启停与合并只在用户明确要求时执行（D-057）。
- 接口见 [API 约定](local-api-contract.md)；部署与回滚见 [Ubuntu 部署说明](../deploy/ubuntu/README.md)；验收证据见 [EC2 部署验收](EC2部署验收.md) 与[可靠性与解耦验收](可靠性与解耦验收.md)。
