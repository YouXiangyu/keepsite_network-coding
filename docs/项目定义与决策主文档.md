# 个人电影票整理与多端同步：当前产品规格

版本：0.15。更新日期：2026-10-21，Asia/Shanghai。

本文是唯一有效的产品规格；实施顺序与验收见[开发计划](开发计划.md)。本次仅重定产品范围和技术方向，尚未改造应用代码。现有代码、旧验收结果与新版目标须分别判断。

旧规格、开题资料、设计图和旧接口说明已按用户要求移出当前文档目录，可从改版前 Git 检查点 `d7945d8` 追溯；旧内容不再构成开发要求。

## 1. 产品定位

为同一用户在电脑、手机和平板之间整理、查看和同步电影票。以简单业务承载状态同步、异步网络处理和设备间文件传输的课程实践。

业务主线：

**登录 → 上传电影票照片 → OCR 提取电影信息 → 检索并下载海报 → 显示海报封面 → 查看、纠错、删除 → 本人设备同步。**

- 首版只处理电影票，一张原票照片对应一条记录。
- 首先交付统一的响应式 Web 应用，Web 完成后继续开发 Android App。
- 票根记录属于本人，不包含朋友推荐、社交发布、票务交易或验票。
- 服务端长期保存元数据，设备长期保存原票照片与海报；服务端临时处理和必要的中继传输允许产生流量。

## 3. 最小业务与界面

### 3.1 账号与入口

- 保留现有 Google 登录、邮箱注册登录、邮箱验证与找回密码。未登录只显示认证入口。
- 每个账号的票根、任务、设备和媒体访问独立；新用户从空票夹开始，不复制旧收藏、分享或社区测试模板。
- Web 使用同源接口、服务端 HttpOnly 会话和 CSRF 防护。退出、会话失效或换号时停止旧请求、状态订阅和设备传输，旧响应不能影响新会话。
- 退出不等于删除记录或设备文件；未登录或其他账号不得在应用中查看、索取或传输这些文件。

### 3.2 电影票记录

- 保留原票照片；海报是可替换的封面，不能覆盖或丢弃原票。
- 识别字段沿用电影票所需的片名、影院、影厅、座位和放映时间；无可靠结果留空，允许用户纠错，不扩展演员、剧情等内容库。
- 系统记录字段来源、创建与更新时间、记录版本、处理状态、媒体清单及媒体可用状态。不保留分类、标签、稀有度、节日或模型字段。
- 用户填写和纠错优先于识别结果；异步旧结果不得覆盖更新后的输入、用户字段或已删除记录。
- 不持久保存 OCR 全文，不把原票敏感内容写入日志。只保留业务需要的电影信息。
- 海报未找到、匹配不可靠或下载失败时使用原票封面，显示真实处理结果，允许重试或纠错。海报更换后仍保留原票。

### 3.3 首版页面与操作

- 票夹：图片主导的响应式列表，能打开票根详情并看到处理或缺图状态。
- 上传与编辑：选择原票照片、提交、查看识别进度、纠正字段。
- 详情：海报封面、原票查看、电影信息、删除入口和当前设备的图片可用情况。
- 设备与同步状态：显示本人在线设备、正在传输、等待来源设备、传输失败或本机存储不足等状态。
- 账号入口：登录、退出及既有必要账号操作。
- 不沿用旧五页面结构、徽章墙或社交导航。首版不额外增加推荐算法、复杂搜索筛选、个人主页装修或完整离线业务。

### 3.4 删除与设备副本

- 删除作用于本人各端；服务端提交删除标记，其他设备联网同步后清除该记录及不再被其他记录引用的文件。
- 离线设备在重新连接前可能仍有旧副本；收到删除后不得用旧数据复活记录。
- 退出、清除浏览器存储和删除票根是不同操作。清除本机存储可能丢失本机仅有的图片副本，不自动删除其他设备的记录。
- 本轮文档调整不删除既有数据库、S3 文件、模型、用户照片或回滚数据；旧实现的数据迁移按开发计划单独执行。

## 4. 三条技术主线

### 4.1 Redis、元数据与实时状态

工程约定：继续使用持久数据库保存票根元数据和变更记录，Redis 承担热点缓存、共享运行状态与异步队列。按用户和业务划分键空间，不为每个用户启动独立 Redis 实例，不把图片二进制放进状态响应或缓存快照。

- 首次进入按页批量读取元数据；快照与后续增量之间有明确游标边界。
- 后续按游标取得新增、修改、删除和处理结果变化，避免周期性返回全账户快照。
- WebSocket 推送状态变化或增量提示。断线重连后按最后确认游标补拉，游标过期则重新校准快照；通知不能代替持久事实。
- 元数据修改与变更记录在同一事务提交；Redis 缓存和通知可从持久数据恢复，服务重启或缓存丢失不能丢掉已确认记录。
- 写操作带稳定操作标识，重复提交不重复创建记录。按字段提交修改，同字段以服务器应用顺序为准，不同字段分别保留；删除优先于之后到达的旧修改。
- 本机图片清单与处理状态分开：服务端处理完成不代表每台设备已下载完成。
- Redis 引入后的性能提升须用相同负载测量；不把使用 Redis 本身等同于完成读写分离或多级缓存设计。

### 4.2 OCR 与海报异步流水线

**设备保存原票 → 临时上传 → 入队 → OCR → 海报检索与下载 → 发布元数据与状态 → 设备接收海报并确认 → 清理临时媒体。**

- 上传请求在接收和登记任务后返回，OCR 和网络抓取不阻塞请求处理。
- 已确认任务在数据库中保留可恢复的处理意图。登记后入队中断或 Redis 队列丢失时，能够重新投递或明确标为可重处理，不能永久停在待处理；消费者重复执行仍须幂等。
- 工程默认复用 Redis Streams 的消费者组、确认与待处理恢复机制，不另引入一套消息中间件。
- OCR 计算与海报网络下载分别设置并发、超时和资源限制；计算不能占住实时接口或事件循环，网络等待不占数据库写事务。
- 任务可重放；消费者在结果持久提交后确认，失败按有限次数退避重试，超过限制显示失败。幂等和输入版本检查防止重复记录、旧海报覆盖和删除后复活。
- 工程默认：首版只接入一个经过验证的海报来源。匹配依据为片名，并用票面放映时间辅助同名影片判断；不可靠时保留原票。
- 爬虫处理下载超时、限流、响应异常、图片类型与大小校验；记录来源页面或资源标识。来源和“高清”的分辨率验收值在实施时通过实际样本确定，不能承诺每部影片都有海报。
- 不因本轮允许中继流量而引入付费 OCR、付费模型或运行时生图 API。
- 设备须持久保存并校验文件后才确认接收；仅收到网络字节不能当作保存成功。未确认时明确显示“待接收”。
- 临时文件采用有界保留与可观察清理。具体期限属于实施参数；过期的未交接结果标明失效，可从设备保存的原票重新处理，不得伪称已完整保存，也不得清掉唯一已确认保存的原票。

### 4.3 本人设备间图片传输

工程约定：Web 使用 WebRTC DataChannel 传输图片，WebSocket 可复用为信令通道；设备身份和会话仍由服务端鉴权。

- 同账号设备上线后交换所持文件清单，按 SHA-256 哈希识别和校验内容，只传本机缺少的原票或海报。
- 服务器保存用户与文件的归属关系、必要的设备身份和媒体清单；在线状态、寻址候选和连接信令有有效期，不把历史 IP 当可用地址。
- 直连优先；需要时通过 TURN 中继，分别统计直连与中继字节数。中继不构成云端图片备份。
- 分块传输、流量背压、取消和中断恢复均须有明确状态；已存在并校验通过的文件不重复完整传输。
- 哈希是内容标识，不是访问凭证。设备登记、信令、文件请求与中继凭据均绑定当前用户，不同账号即使知道哈希也不能取得图片。
- 源设备离线或不可达时，新设备先显示元数据和等待状态；来源重新可用后继续补图。
- 所有设备副本丢失时，如实显示无法恢复原文件，不虚构下载地址或可用设备。设备在线状态只能说明可联系，不能保证其文件仍存在。

## 5. 本地媒体与平台边界

本地保留原票和海报是 P2P 的必要条件；本版不实现离线新增、离线修改排队、离线 OCR 或完整本地业务数据库。

- Web 以浏览器可用的持久文件存储保存媒体，按账号隔离；存储实现和容量管理在开发阶段验证。
- 浏览器空间不足、权限限制或存储被清理时，应用显示真实状态。不能把浏览器存储描述为永久可靠备份。
- 手机和平板 Web 的传输验收以页面前台在线为基线；不承诺锁屏、后台冻结或浏览器关闭后持续传输。
- Android 放在 Web 完成后的独立阶段，沿用既有原生 Kotlin 方向，工程位于 `demo/` 之外。复用同一套账号、元数据、任务状态与设备传输协议，不恢复已删除的旧业务。
- Android 具体会话接入、文件持久化与后台行为在该阶段验证；不把原生客户端作为首版 Web 完成条件。

## 6. 验收与非目标

首版验收同时覆盖业务闭环、跨账号隔离、异步失败恢复、状态断线补拉、直连与中继、源端离线等待、存储不足和删除传播。

课程技术证据包括：状态请求数与传输字节、缓存命中及接口延迟、队列等待与端到端耗时、失败任务恢复、图片校验与同步成功率、直连/中继流量。测量方法和样本见开发计划，未经实测不宣称高并发能力或节流比例。

明确不做：3D/2.5D 与深度推理、分类标签、徽章稀有度、节日特效、朋友推荐与社区、无互联网近场分享、票务交易、完整离线业务、云端长期图片备份，以及首版 Android。

旧运行环境与证据见[EC2 部署验收](EC2部署验收.md)、[可靠性与解耦验收](可靠性与解耦验收.md)。这些记录描述旧实现，不能作为本版新能力已完成的证明。

## 7. 技术依据

- [Redis 缓存](https://redis.io/docs/latest/develop/use-cases/cache-aside/)：缓存与持久数据的职责及失效处理。
- [Redis Streams](https://redis.io/docs/latest/develop/data-types/streams/)：消费者组、确认、待处理与重放。
- [WebRTC 连接](https://webrtc.org/getting-started/peer-connections)：数据通道与连接信令。
- [TURN 中继](https://webrtc.org/getting-started/turn-server)：直连不可用时的中继传输。
