# 个人电影票整理与多端同步：当前产品规格

版本：0.20。更新日期：2026-10-24，Asia/Shanghai。

本文是唯一有效的产品规格；实施顺序、当前进展与验收见[开发计划](开发计划.md)。现有代码、旧验收结果与新版目标须分别判断，不能把规格中的目标当成已经完成的能力。

旧规格、开题资料、设计图和旧接口说明已按用户要求移出当前文档目录，可从改版前 Git 检查点 `d7945d8` 追溯；旧内容不再构成开发要求。

## 1. 产品定位

软件正式名称为小写 `keepsite`。2026-10-24 用户确认同时统一技术标识，采用显式迁移保留原账户、数据库、原票、备份与旧应用数据；不以重新创建空数据代替迁移。历史证据和迁移源标识保留当时名称，不伪称云资源已经切换。

为同一用户在电脑、手机和平板之间整理、查看和同步电影票。以简单业务承载状态同步、异步网络处理和设备间文件传输的课程实践。

业务主线：

**登录 → 上传电影票照片 → OCR 提取电影信息 → 检索并下载海报 → 显示海报封面 → 查看、纠错、删除 → 本人设备同步。**

- 首版只处理电影票，一张原票照片对应一条记录。
- 首先交付统一的响应式 Web 应用，Web 完成后继续开发 Android App。
- 票根记录属于本人，不包含朋友推荐、社交发布、票务交易或验票。
- 数据库长期保存元数据，私有 S3 长期保存原票照片与海报；浏览器保存可回收缓存，P2P 用于加速。已确认云端保存的内容不因清除浏览器存储而丢失。

## 3. 最小业务与界面

### 3.1 账号与入口

- 保留现有 Google 登录、邮箱注册登录、邮箱验证与找回密码。未登录只显示认证入口。
- 同一应用账户支持独立的邮箱密码和 Google 登录方式：密码账户可在账户设置中验证并绑定 Google，Google 账户可验证邮箱并添加密码登录。绑定必须证明待绑定身份的控制权，不因邮箱文字相同自动合并；绑定后保持原账户 ID、票根和媒体归属不变。已归属另一个应用账户的身份明确报冲突，不自动迁移或合并数据。
- 2026-10-24 用户确认两种登录方式可以使用不同邮箱。本轮沿用当前 Cognito 邮箱唯一约束；Google 先登录时，密码身份使用另一个可验证邮箱，不改用户池、不强制转移邮箱，也不承诺同邮箱双身份。
- 每个账号的票根、任务、设备和媒体访问独立；新用户从空票夹开始，不复制旧收藏、分享或社区测试模板。
- Web 使用同源接口、服务端 HttpOnly 会话和 CSRF 防护。退出、会话失效或换号时停止旧请求、状态订阅和设备传输，旧响应不能影响新会话。
- 退出不等于删除记录或设备文件；未登录或其他账号不得在应用中查看、索取或传输这些文件。

### 3.2 电影票记录

- 保留原票照片；海报是可替换的封面，不能覆盖或丢弃原票。
- 识别字段沿用电影票所需的片名、影院、影厅、座位和放映时间；无可靠结果留空，允许用户纠错，不扩展演员、剧情等内容库。
- 系统记录字段来源、创建与更新时间、记录版本、处理状态、媒体清单、云端保存状态及本机缓存状态。不保留分类、标签、稀有度、节日或模型字段。
- 用户填写和纠错优先于识别结果；异步旧结果不得覆盖更新后的输入、用户字段或已删除记录。
- 不持久保存 OCR 全文，不把原票敏感内容写入日志。只保留业务需要的电影信息。
- 海报未找到、匹配不可靠或下载失败时使用原票封面，显示真实处理结果，允许重试或纠错。海报更换后仍保留原票。

### 3.3 首版页面与操作

- 票夹：图片主导的响应式列表，能打开票根详情并看到处理或缺图状态。
- 上传与编辑：选择原票照片、提交、查看识别进度、纠正字段。
- 详情：海报封面、原票查看、电影信息、删除入口和当前设备的图片可用情况。
- 设备与同步状态：显示云端上传/保存、本机缓存、本人在线设备、P2P 或云端下载、传输失败和缓存空间不足等状态。
- 账号入口：登录、退出及既有必要账号操作。
- 不沿用旧五页面结构、徽章墙或社交导航。首版不额外增加推荐算法、复杂搜索筛选、个人主页装修或完整离线业务。

### 3.4 云端保存、缓存与删除

- 原票在 S3 保存、内容与归属核验通过，且数据库已提交本人记录的有效媒体引用后，才显示原票“已保存到云端”；任务已创建或获得上传地址不等于保存成功。
- 上传失败或结果未知时显示未完成，保留当前选择或草稿供核对与重试，使用稳定操作标识避免重复创建；未上传成功的内容不能承诺在清除浏览器数据后恢复。
- 清除本机缓存只移除本机文件；用户重新登录且服务可用时，可从云端取回票根元数据、原票与海报，无需其他设备在线。缓存不足不阻止读取云端记录，可通过授权下载直接展示图片。
- 删除票根先提交删除标记并撤销后续业务读取与下载授权，再同步移除各端关联与缓存；旧修改不能复活记录。尚未联网的设备在下次同步时处理删除。
- 云对象只在无有效引用且满足清理策略时回收；不能删掉其他记录仍在引用的文件。现有 S3 版本控制会保留历史版本，普通删除不代表所有版本立即清空；版本回收策略在实现阶段明确。
- 退出不删除云端或本机内容，换号不串用缓存。已经签发的短期下载地址有自身有效期，不承诺退出或业务删除会瞬间撤销该地址。
- 2026-10-21—22 的规格调整未删除既有数据库、S3 文件、模型、用户照片或回滚数据；后续实际迁移和清理按开发计划及明确授权执行。

## 4. 三条技术主线

### 4.1 Redis、元数据与实时状态

工程约定：继续使用持久数据库保存票根元数据和变更记录，Redis 承担热点缓存、共享运行状态与异步队列。按用户和业务划分键空间，不为每个用户启动独立 Redis 实例，不把图片二进制放进状态响应或缓存快照。

- 首次进入按页批量读取元数据；快照与后续增量之间有明确游标边界。
- 后续按游标取得新增、修改、删除和处理结果变化，避免周期性返回全账户快照。
- WebSocket 推送状态变化或增量提示。断线重连后按最后确认游标补拉，游标过期则重新校准快照；通知不能代替持久事实。
- 元数据修改与变更记录在同一事务提交；Redis 缓存和通知可从持久数据恢复，服务重启或缓存丢失不能丢掉已确认记录。
- 写操作带稳定操作标识，重复提交不重复创建记录。按字段提交修改，同字段以服务器应用顺序为准，不同字段分别保留；删除优先于之后到达的旧修改。
- 原票云端保存、OCR/海报处理完成、海报云端保存与本机缓存就绪分别记录；服务端完成处理不代表每台设备已下载完成。
- Redis 引入后的性能提升须用相同负载测量；不把使用 Redis 本身等同于完成读写分离或多级缓存设计。

### 4.2 轻量 OCR 与海报异步流水线

**原票上传并确认存入 S3 → 登记处理任务 → 入队 → 轻量 OCR → 海报检索与下载 → 海报保存到 S3 → 发布封面引用与状态 → 客户端按需获取。**

- 上传完成不等待 OCR 和抓取。云对象与数据库不是同一事务，上传意图、媒体引用与任务登记须可重试和核对；原票已上传但引用或任务未提交时能够恢复，不能丢成不可追踪的文件。
- 已确认任务在数据库中保留可恢复处理意图；登记后入队中断或 Redis 队列丢失时重新投递或明确标为可重处理，不能永久停在待处理。工程默认使用 Redis Streams 消费者组。
- 工程首选评估 RapidOCR + ONNX Runtime 的 PP-OCRv6 tiny 中文识别路线，仅运行必要的文字检测与识别；方向处理按样本需要启用，不引入大语言/视觉语言模型或整页文档解析流水线。
- “轻量”以电影票样本的字段准确率、进程峰值内存、冷启动和处理耗时共同判断，不能把模型文件大小当作运行内存。M3 固定验证通过的模型版本、文件哈希、预处理、CPU 线程和并发数；未验证前不宣称已有性能提升。
- OCR 计算与海报下载分别限制并发、超时和资源；计算不占实时接口的事件循环，网络等待不占数据库写事务。消费者结果持久提交后才确认，重试有上限，失败可见。
- 用户纠错、新输入版本和删除优先于旧任务结果。原票云端保存成功后，不因 OCR、抓取或海报上传失败而丢失；失败时继续显示原票并允许重试。
- 工程默认只接入一个经过验证的海报来源，按片名和放映时间辅助匹配；不可靠时保留原票。下载校验类型、大小与内容，记录来源；站点和高清阈值仍在实施时用样本确定。
- 2026-10-24 用户明确选择接入 TMDB API。密钥仅由后端私密环境配置读取，不进入 Git、网页或 APK；TMDB 海报记录电影来源与服务条款，并提供要求的署名，不标作 Commons 的开放许可图片。同名作品、续集和未来上映作品须保守匹配，不以热度代替身份核对。
- 新海报先保存并校验到 S3，再原子发布当前输入版本对应的封面引用；发布失败可恢复，旧引用在新结果就绪前保持有效。无引用产物按清理策略回收。
- 客户端收到并缓存海报只更新本机缓存状态，云端结果不以某台设备领取为完成条件；用户离线不导致已经云存的海报过期。
- 处理临时文件有独立保留期和清理记录；不得把原票或当前海报对象当临时文件删除。不引入付费 OCR/模型或运行时生图 API。

### 4.3 P2P 加速与 S3 兜底

工程约定：WebRTC DataChannel 负责同账号设备间传输，WebSocket 可复用为信令通道；私有 S3 是原票与海报的长期媒体来源。

- 获取顺序为本机有效缓存、可用 P2P、授权 S3。P2P 发现、连接和传输有等待预算；没有在线源设备、连接失败、传输停滞或校验失败时转为 S3，不无限等待其他设备。
- 同账号设备按 SHA-256 比对和校验缓存清单，只传缺少文件；缓存被系统清除时不得继续声称文件可用。服务端保存文件归属，设备在线状态、寻址候选和连接信令均有有效期。
- P2P 直连优先，TURN 使用一家第三方公开提供的免费服务，不在本项目部署 coturn 或其他中继服务器。M3 核实免费条件、账号/凭据、额度限制和目标网络连通性，M5 接入；未满足条件时直接使用 S3。
- 中继尝试受等待预算及免费额度限制；服务不可用、额度不足或存在超额收费风险时转 S3，不自动升级付费套餐，也不退回自建中继。分别统计直连、TURN 和 S3 的请求/字节，取消多余传输，避免双路完整下载。
- 分块、背压、取消、中断恢复与全文件校验均有明确状态；校验后才标为本机缓存可用。缓存写入失败不撤销已经成功的云端保存。
- S3 保持私有、服务端加密与 HTTPS；按账号校验归属，再通过短期授权地址或受保护接口读取。默认评估短期授权直读以减少应用服务器转发，禁止把桶公开或给浏览器长期 AWS 凭据。
- 哈希不是访问凭证。P2P、S3、设备登记、信令和中继凭据均遵循同一账号边界；下载地址不写日志或持久业务字段，到期需要重新授权。
- 云端对象和业务引用均有效时，即使所有设备缓存丢失也能恢复；若对象缺失或授权服务不可用，显示实际错误并允许重试，不伪称已恢复。
- S3 会产生存储、请求与数据传出费用；P2P 主要减少部分云端读取和传输，不能消除存储费。TURN 只使用核验过的免费方案/额度，不能把免费理解为不限流量或无需凭据；版本保留与清理影响 S3 容量，按实际用量验证收益。

## 5. 浏览器缓存、平台与服务可用性

- Web 本地媒体是按账号隔离的可回收缓存。持久存储支持、缓存容量和主动清理在开发阶段验证；清理本机缓存不删除云端记录或对象。
- 本版仍不实现离线新增、离线修改排队、离线 OCR 或完整本地业务数据库。未上传草稿与已云存票根必须区分，不把二者都显示为已保存。
- 手机和平板 Web 以页面前台在线为传输验收基线，不承诺锁屏、后台冻结或浏览器关闭后持续 P2P 传输。
- Android 放在 Web 完成后的独立阶段，沿用 Kotlin 原生方向，工程位于 `demo/` 之外。复用账号、云端媒体、元数据和设备加速协议，不恢复已删除业务。
- 信令服务和 Web/API/鉴权/下载授权入口如何在 EC2 非常驻时提供服务，按用户要求留到后续架构讨论；本次不选择常驻实例或替代部署，不修改开机 58 分钟自动关机规则。
- S3 数据持久存在不等于应用停机期间仍可新登录或取得下载授权；短期地址还受签名凭据有效期限制。当前开发验收以所需服务可用为前提，不承诺全天候访问。

## 6. 验收与非目标

首版验收覆盖业务闭环、跨账号隔离、上传结果核对、异步失败恢复、状态断线补拉、P2P/中继与 S3 降级、清缓存后恢复、缓存空间不足和删除传播。

课程技术证据包括：状态请求数与传输字节、缓存命中及接口延迟、队列等待与端到端耗时、失败任务恢复、图片校验与同步成功率、直连/中继/S3 流量，以及 OCR 字段准确率、峰值内存和耗时。测量方法和样本见开发计划，未经实测不宣称高并发能力或节流比例。

明确不做：3D/2.5D 与深度推理、分类标签、徽章稀有度、节日特效、朋友推荐与社区、无互联网近场分享、票务交易、完整离线业务，以及首版 Android。

旧运行环境与证据见[EC2 部署验收](https://github.com/YouXiangyu/network-coding/blob/d23f04d886d7cd656c542c3f4bd69826906c8c55/docs/EC2部署验收.md)、[可靠性与解耦验收](https://github.com/YouXiangyu/network-coding/blob/d23f04d886d7cd656c542c3f4bd69826906c8c55/docs/可靠性与解耦验收.md)。这些记录描述旧实现，不能作为本版新能力已完成的证明。
