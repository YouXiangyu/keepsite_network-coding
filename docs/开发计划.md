# 开发计划

创建日期：2026-10-20。基线：`main` `eb486c9`。产品规则以[主文档](项目定义与决策主文档.md)为准；本文只写执行顺序、工作包与验收。

## 0 阅读顺序

1. `AGENTS.md`；修改 Web 时加读 `demo/AGENTS.md`。
2. [主文档](项目定义与决策主文档.md)、本计划、[API 约定](local-api-contract.md)。
3. `README.md`、`backend/README.md`、`demo/README.md` 中的责任地图。

不读 `docs/history/` 与 `docs/sources/`，除非工作包点名（例如 WP-14 点名开题 A §6）。

## 1 执行规则（硬性）

1. 每个工作包一个分支（`codex/wp-NN-<短名>`）、一个 PR；按逻辑单元提交，不 amend、不强推。
2. 注释只写代码无法表达的约束；不写解释代码在做什么或本次改了什么的注释。
3. 不提交临时脚本、调试输出、截图与本地产物；一次性脚本放 `.cache/`，完成后删除。
4. 除本计划指定外不新增文档。接口变化更新 `docs/local-api-contract.md`，模块职责变化更新对应 README 的责任地图，修改的文档标注更新日期。产品规则需要变化时先停下请用户确认，确认后再更新主文档。
5. 测试断言真实行为。只允许替换外部网络服务（Cognito、TMDB、维基百科；对象存储用现有本地实现），以及沿用现有约定、需要模型权重的推理步骤（真实推理测试按现有开关单独运行）。不用模拟成功代替功能。
6. 不加兼容映射、别名或兜底补丁，优先修正调用逻辑。schema 变更写显式迁移，不静默接受旧结构。
7. 密钥只进环境文件（服务器 `/etc/memoverse.env`、本机受限文件），不进 Git、日志或前端。
8. 不部署、不合并、不启停 EC2，不修改 AWS、Cognito 或 Google 控制台配置；需要时写进 PR 描述交给用户。
9. `Backend tests`、`Frontend tests`、`deployment-recovery` 必须通过；WP-10 新增 `Android tests` 后同样必须通过，并更新 `AGENTS.md` 的合并检查清单。
10. 计划与代码、文档或用户新指令矛盾时，停在受影响步骤并报告用户，不自行选择。
11. 第 6 节“待用户确认”的项须在对应工作包开工前由用户确认；仍未确认时停在该工作包并报告，不按默认值推进。
12. PR 描述列出：已完成的验收项、未覆盖项、需要用户执行的操作（配置、部署、真机验收）。

## 2 顺序与用户原话

用户原话：“先做多端同步（账号资料同步），OCR自动识别并提取电影海报，自动分类，移动端的开发”（D-047）。

- 多端同步：WP-01、WP-02 完成服务器侧同步与 App 鉴权；App 接入在 WP-13。
- OCR 与自动分类：WP-03 先修正生成触发与标签匹配，WP-04 实现识别。自动分类是海报与徽章的前置依赖。
- 电影海报：WP-05。徽章（用户后续追加）：WP-06 至 WP-09。
- 移动端：WP-10 至 WP-13；近场分享 WP-14 排在移动端最后。
- 依赖允许时可以并行：WP-02 与 WP-01 并行；WP-06 不依赖 WP-04、WP-05。

## 3 现状要点（`main` `eb486c9`）

- 后端调用链：`app.py` 装配 → `api.py` HTTP → `services/` 业务 → `store.py`（SQLite schema 2，`require_schema2_root` 拒绝其他版本）。`state.py` 返回账号全量快照。
- 账号有单调递增的 `users.revision`；收藏有 `version`，PATCH/DELETE 版本不符返回 409；删除是硬删除，没有墓碑，也没有增量接口。
- 鉴权是 BFF 模式：`auth.py` 加密保存 Cognito 令牌，浏览器只持有不透明会话 Cookie（7 天）；写请求校验 Origin、`X-MemoVerse-Client: web` 与 `X-CSRF-Token`。Google 登录走 Cognito 托管页与 PKCE，回调固定为网站 `/api/auth/callback`。
- 生成：`jobs.py` 单线程 `JobWorker` → `generation/repository.py` 领取 → `generation/pipeline.py` 下载原图、调用 `relief_engine.py` 子进程（`anyimage_worker.py`）、上传 → repository 发布并核对输入版本。重型依赖（onnxruntime、trimesh）由 `scripts/setup-anyimage.*` 固定安装在 `.cache/anyimage-deps`，缺失时相关测试跳过。
- `services/collections.py`：`infer_tag` 只匹配本人记录；`update` 在 `art` 改变时也会重新生成。
- 展示分类 `contracts.py::Category` 为 `movie`、`travel`、`daily`、`exhibition`（电影、旅行、日常、展览）。Web 新建表单要求填写标题与日期。
- 对象：图片 `media/<sha>.<ext>`，模型 `models/<id>/{model.glb,depth.npy,geometry.json}`，由 `template.validate_model_outputs` 校验；EC2 角色只允许读写 `media/*`、`models/*`。`collect_item`、`generation/repository.py` 与 `backups.py` 假定模型属于收藏原图。
- 初始模板：`MEMOVERSE_TEMPLATE_DIR` 下 manifest 加 SHA 校验（`template.py`），文件不入 Git。模板复制的收藏没有显式来源标记。
- 尚无 OCR、海报、徽章与 Android 工程。

## 4 工作包

每包列出：目标、依赖、修改范围、约束、验收、不做。开工前先核对所列路径，与现状不符时按规则 10 处理。

### WP-01 服务器同步接口

- 目标：App 离线修改联网后能幂等上传、合并，并增量拉取服务器变化（收藏与个人资料）。依赖：无；开工前确认 C7。
- 范围：`store.py`（schema 3 与显式迁移：变更序号、墓碑、已处理操作）、新增 `services/sync.py`、`api.py`、`contracts.py`、`backups.py`、`scripts/restore-account-backup.py`、`scripts/inspect-generation.py`、API 约定、`backend/README.md`。
- 约束：
  - 拉取 `GET /api/sync/changes?cursor=`：返回游标之后的收藏与资料变化、墓碑及新游标；游标使用账号级单调序号（可基于 `users.revision`），不用时间戳。
  - 上传 `POST /api/sync/operations`：批量操作 `{operationId, entity, entityId, action, baseVersion, base, changes}`；同一 `operationId` 重放返回首次结果。
  - 合并按第 6 节 C7 的确认结果实现；冲突时返回服务端当前值，不覆盖任何一方。
  - 删除写墓碑；针对已删除实体的旧操作返回“已删除”，不复活记录。
  - 新建复用现有草稿 ID 幂等与 `POST /api/media` 上传；同步新建与 Web 新建调用同一业务函数，同样触发生成。
  - Web 写入、生成完成与识别结果发布也产生变更序号；Web 现有接口行为不变。
- 验收：同一操作重复提交不重复创建；删除后旧设备的修改不复活；冲突按 C7 处理且双方值都可取回；游标拉取不漏不重；跨账号访问被拒绝；在现有数据副本上 schema 2→3 迁移成功，失败时原库不变；备份与恢复包含新表。
- 不做：CRDT、实时推送、整库上传、分享同步（WP-14）。

### WP-02 App 鉴权接口

- 目标：Android 不依赖 Cookie 完成邮箱登录、注册验证、找回密码与 Google 登录。依赖：无。
- 范围：`backend/auth.py` 及其测试、API 约定、`backend/README.md` 配置表。
- 约束：
  - App 请求带 `X-MemoVerse-Client: android` 与 `Authorization: Bearer <会话凭据>`；凭据与 Web 会话同表、同有效期与刷新逻辑，由响应体返回，不设 Cookie。
  - Bearer 请求不做 Origin 与 CSRF 校验；Cookie 请求保持现有校验；同一请求携带两种凭据时拒绝。
  - Google：App 生成 PKCE、state 与 nonce，经 Custom Tabs 打开 Cognito 托管页并回调到 App 重定向地址；后端新增交换接口，用授权码与 verifier 换取令牌、校验 nonce 后建立会话。允许的重定向地址来自环境配置；默认复用现有无密钥客户端，由用户在控制台添加回调地址。
  - 退出时撤销会话与上游刷新令牌，与 Web 一致。
- 验收：Bearer 请求只能访问本人数据；缺失或伪造凭据返回 401；Cookie 请求缺 CSRF 仍返回 403；混用凭据被拒绝；交换接口拒绝错误 verifier、错误 nonce 与未登记的重定向地址；令牌与授权码不出现在日志。
- 不做：WebView 登录；在 App 内保存 Cognito 令牌。

### WP-03 生成触发与标签匹配修正

- 目标：`art` 不再触发生成（D-051）；标签匹配跨用户并排除模板记录（D-049）。依赖：无；开工前确认 C3。
- 范围：`services/collections.py`（`update` 的重建条件、`infer_tag`）、后端测试、`demo/README.md` 的触发说明。
- 约束：保持现有关键词规则与“占比最高、无命中不设标签”；统计口径按 C3。
- 验收：只改 `art` 不新建任务、模型不变；换图仍新建任务；A 手填的标签能被 B 新建的同名收藏命中；模板记录不计数；B 修改标签不改变 A 的记录；已保存的收藏不随后续数据变化。
- 不做：关键识别字段触发（WP-04、WP-05、WP-07 各自接入）。

### WP-04 服务端 OCR、自动分类与字段提取

- 目标：保存图片后自动识别文字、判断类型、填写字段与展示分类。依赖：WP-03；开工前确认 C1、C2、C4。
- 范围：生成 worker 增加识别阶段（`jobs.py`、`generation/`、新识别模块与子进程入口）、`contracts.py`（识别字段与来源）、`store.py` 迁移、`state.py`、`backups.py`、OCR 依赖安装与校验（扩展 `scripts/setup-anyimage.*` 或新增同类脚本）、`THIRD_PARTY.md`、`demo/src/features/collections/`（识别状态与字段）、API 约定。
- 约束：
  - OCR 使用免费 CPU 引擎（如 RapidOCR / PP-OCR ONNX），固定版本与权重 SHA；按 `relief_engine.py` 的子进程方式运行，在同一串行 worker 中执行，不与 MoGe2 并发。
  - 自动分类是纯函数：输入 OCR 文本行，输出类型与字段；关键词规则在代码中，可单测。
  - 识别结果用独立短事务发布（先于浮雕），核对输入版本；只填空字段并记录来源；换原图时替换来源为识别的字段，保留用户填写的字段。
  - OCR 全文不持久化、不写日志；白名单字段之外的内容（姓名、证件号等）丢弃。
- 验收：每种类型至少 3 份由真实样例转写的 OCR 文本夹具，分类与字段正确（样例图片不入 Git）；无文字图片归为其他照片并照常生成浮雕；识别失败不阻止保存与生成；识别期间用户的编辑不被覆盖；数据库与日志不含姓名、证件号；在本机测量 OCR 与 MoGe2 串行执行的峰值内存并写入 PR，超过服务 `MemoryMax=1500M` 时停下报告。
- 不做：AI 分类、付费 OCR、Android 离线 OCR（WP-12）。

### WP-05 电影海报

- 目标：电影票按片名取得海报，作为封面与浮雕输入。依赖：WP-04。
- 范围：新海报模块（TMDB、维基百科客户端与选择规则）、`store.py`（海报缓存：来源与影片 ID 对应图片资产）、生成流水线、`state.py`、`backups.py`、`collect_item`、前端卡片与详情、API 约定、`THIRD_PARTY.md`（TMDB 署名要求）。
- 约束：
  - Key 从环境变量 `MEMOVERSE_TMDB_API_KEY` 读取；缺失时只用维基百科。
  - 同名多部选上映日期最接近放映时间的一部；无可信匹配时用票的照片。
  - 下载的海报经 `media.py` 同样的格式与尺寸校验，作为不可变图片资产存入现有 `media/` 前缀（不新增 S3 前缀，避免改 IAM）；同一影片跨账户复用文件，只为当前账户新增授权。
  - 收藏保留票的照片为原图，另记“浮雕输入资产”；把“模型属于原图”的假设改为“模型属于浮雕输入资产”。
  - 修改片名或放映日期触发重新检索与生成；外部请求设超时与有限重试，失败时退回票的照片并可重试。
- 验收：用固定响应样例覆盖 TMDB 命中、同名多部选择、无 Key 走维基百科、两者都无结果用票的照片；同一影片第二次不再请求外部；页面显示来源与“仅限小范围非商用测试”；CI 不访问真实 TMDB 或维基百科。
- 不做：演职员、简介等详情抓取。

### WP-07 徽章生成与浮雕

- 目标：交通票、景区与展览门票生成城市徽章浮雕。依赖：WP-04、WP-06；开工前确认 C5。
- 范围：新徽章模块（抽取、图层合成、分层高度网格与 GLB 导出）、生成流水线分支、`store.py`（抽取结果）、`state.py`、`backups.py`、前端详情显示城市与稀有度。
- 约束：GLB 导出沿用 `anyimage_worker.py` 的网格与 trimesh 写法，并以同样的子进程边界运行；产物沿用 `models/<id>/` 三件套与 `validate_model_outputs`（若须调整校验，同步备份恢复）。抽取使用服务端随机种子，持久化种子与结果，同一输入版本重放结果一致；用户修正城市、站点或日期后重新抽取；未覆盖城市用通用徽章。
- 验收：珠海→北京同时含两城元素；重新打开结果不变；修正城市后结果更新；固定种子抽样 10,000 次，各稀有度频率与配置概率相差小于 1 个百分点；GLB 在 Web 查看器正常加载并遵守 40°；不调用任何生图接口。
- 不做：稀有度防刷、徽章交换。

### WP-08 节日特效

- 目标：票面日期是节日时，海报与徽章带节日特效。依赖：WP-05、WP-07；开工前确认 C6。

- 验收：十个节日在 2025—2030 年的判定与权威日历对照样例一致；非节日无特效；修改日期后特效随之更新。
- 不做：C6 未选定的特效形式。

### WP-10 Android 工程骨架与本地优先存储

- 目标：可安装的 Kotlin + Compose App：登录、按账号隔离的本地库与文件、拍照与导入保存。依赖：WP-01、WP-02。
- 范围：新目录 `android/`（Gradle Kotlin DSL，依赖固定版本）、`.github/workflows/` 新增 `Android tests`（构建与单元测试）、`AGENTS.md` 合并检查清单、`README.md` 技术栈表。
- 约束：Room 与文件目录按用户 ID 分区；会话凭据用 Android Keystore 加密保存；邮箱与 Google 登录走 WP-02 接口；服务器地址由构建配置注入，开发时模拟器经 `10.0.2.2` 访问本机后端；minSdk 按用户真机确认（默认 26）。
- 验收：首次必须登录；断网可新建、编辑，重启后仍在；换号后看不到前一账号数据，且前一账号数据仍保留；单元测试覆盖存储与账号隔离；CI 通过。
- 不做：同步（WP-13）、近场（WP-14）。

### WP-11 Android 界面与浮雕查看器

- 目标：按 V1–V5 实现收藏首页、分类、探索（示例）、朋友分享、我的（含徽章墙）、详情与编辑；原生浮雕查看器。依赖：WP-10。

- 约束：查看器用 Filament 或基于它的 SceneView 加载同一 GLB；总偏转不超过 40°、触点所在的边角下压，逻辑与 `demo/src/relief-angle.ts` 一致并有单元测试；生成状态（二维、处理中、就绪、失败）真实可见。
- 验收：五个页面结构与 V1–V5 对应；查看器角度与方向单元测试通过；无模型时显示原图；离开页面后释放渲染资源。

### WP-12 Android 离线 OCR

- 不做：离线浮雕生成、离线分类。

### WP-13 Android 同步接入

- 目标：本地修改进入 Outbox，联网后由 WorkManager 上传与拉取，并下载完整本地副本。依赖：WP-01、WP-11；开工前确认 C7。
- 范围：`android/` 存储、同步与冲突界面；服务端只在发现 WP-01 缺陷时修改并补测试。
- 约束：本地修改与 Outbox 写入同一 Room 事务；先上传图片再提交新建操作；冲突在界面展示双方值供用户处理；收到墓碑删除本地记录；下载原图、模型与派生资产形成完整副本；未同步内容不被清理；清理缓存只删临时文件。
- 验收：断网新建、编辑、删除，联网后 Web 可见且一致；冲突不静默丢失；删除后旧设备上线不复活；同步中途断网可恢复且不重复创建；空间不足时显示未完成。
- 不做：实时推送。

### WP-14 近场分享

- 目标：两台 Android 在无互联网时分享收藏。依赖：WP-13；开工前确认 C8；协议语义参照开题 A §6。
- 范围：`android/` 新模块（纯 Kotlin 协议核心、Wi-Fi Direct 发现与连接、前台服务传输、导入）；服务端同步扩展“收到的分享”（`services/sync.py`、`services/social.py`），上传的 GLB 经 `template.validate_glb` 校验；协议规格写入 `docs/近场分享协议.md`（本计划指定的唯一新增文档）。
- 约束：一套版本化协议，含版本协商、提议、接收或拒绝、清单、续传偏移、数据帧、校验、提交、回执、取消与错误；带长度前缀的 JSON 加二进制帧；限制包大小、文件数、类型与路径；配对用二维码或短码带外确认。
- 验收（自动化）：JVM 回环测试覆盖正常传输、拒绝、取消、断开后续传、损坏文件校验失败不导入、重复包不重复导入、版本不兼容在协商阶段拒绝；收到的分享同步后 Web 分享页可见。验收（用户）：两台真机按 PR 中的测试清单执行。
- 不做：iOS、跨公网、多人 P2P、Nearby。

## 6 待用户确认

- **C1 类型到展示分类（草案）**：电影票→电影；交通票、景区门票→旅行；展览门票→展览；饮品标签、购物小票、其他照片→日常。用户手选的分类优先。
- **C2 饮品标签与购物小票的字段（草案）**：饮品标签提取名称；购物小票提取店名与日期。
- **C3 标签统计口径**：默认只统计用户自己新建并手填标签的记录；初始模板复制的记录（即使之后被编辑）与来源为朋友推荐的收藏都不计入。
- **C4 识别时机**：默认保存后异步识别、只填空字段，Web 新建允许只提供图片（标题、日期可留空，界面显示“识别中”）。备选：保存前等待识别结果预填表单。
- **C5 景区、展览门票识别不到城市**：默认不生成徽章，改用照片浮雕。
- **C6 节日特效**：默认作为海报浮雕与徽章的静态装饰层（来自素材库），不做查看器动画；默认只在节日当天生效，国庆为 10 月 1—7 日。
- **C7 同步冲突**：默认沿用开题 A §7.3：不同字段的修改自动合并；同一字段冲突时保留双方值并提示用户选择。
- **C8 近场分享**（WP-14 开工前）：默认元数据、封面图与 GLB 到齐即视为成功；原票照片可能含姓名与证件号，默认不发送，由发送者勾选；同一快照重复接收不新增；他人转发视为新来源；原作者的新版本作为新包；取消后的临时文件 24 小时后清理；续传需对端身份与包一致，无需再次确认；删除后允许主动重新接收。
