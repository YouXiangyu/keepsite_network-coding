## 3. 串行里程碑

### M1 — 收窄业务、定义数据与迁移边界

交付：
- 电影票列表、上传编辑、详情和必要设备状态的页面范围；移除分类标签、探索分享、徽章节日及浮雕入口。
- 统一票根字段、字段来源、处理状态、媒体状态、版本、删除标记与操作标识。
- 新用户空票夹；移除旧社交/模型初始模板依赖。
- 提出旧数据库与云端文件的迁移清单，保留用户原票和可恢复备份；不得因为新规格删去字段就直接删除用户文件、数据库、模型缓存或 S3 对象。
- 在隔离数据上迁移并验证；已取消功能的调用链整体退出，不保留旧 API 映射来维持两套业务。

验收：匿名门禁与双账号隔离继续有效；新账号不再产生旧模板内容；新字段和页面一致；可区分“尚未处理”和“图片尚未在本设备保存”。

### M2 — 持久元数据、Redis 与设备文件基础

交付：
- 数据库保存元数据、操作幂等记录及持久变更日志；Redis 保存可重建缓存、在线状态与队列。
- 数据修改与变更日志同事务，定义缓存更新/失效策略与故障恢复。
- Web 按账号持久保存原票、海报和本机媒体清单，校验哈希；完成本机保存后才允许把原票交给临时处理链路。
- 临时上传具有用户、记录和输入版本归属；下载与交接确认不可跨账号。
- 定义上传类型、文件大小、存储失败和本机空间不足的行为；沿用现有 JPG/PNG/WebP、12 MiB 上限作为初始工程值，实测后再调整。

验收：Redis 重启不丢已确认元数据；重复操作不产生重复记录；浏览器刷新和重启后可读取已确认文件；清空浏览器存储后能正确报告缺图；其他账号不能读取文件。

### M3 — OCR、海报与异步状态

交付：
- Redis Streams 生产者消费者流水线：入队、OCR、单一来源海报检索下载、结果持久发布、设备领取确认、临时清理。
- 已确认任务须有数据库中的可恢复处理意图；登记后入队中断或 Redis 队列丢失时重新投递或明确标为可重处理，不能永久等待。具体采用事务待投递记录还是扫描补投在本阶段确定。
- OCR 字段限定为片名、影院、影厅、座位和放映时间，用户字段优先；没有可靠结果时留空。
- 在开发阶段核实 OCR 本地引擎、海报站点、稳定获取方式和许可范围，记录可复跑样本及海报分辨率目标。不得把旧 TMDB 主源规则直接当成用户已重新确认的爬虫方案。
- 计算与网络任务使用独立的并发限制；配置超时、退避、最大重试和失败状态。
- 原图更换或影响海报匹配的字段修改后更新输入版本；迟到任务不覆盖新数据。
- 客户端校验并持久保存海报后确认交接。原票已在设备保存；临时结果无人领取直到过期时显示失效并允许重新处理，不冒充已同步。

验收：上传响应不等待 OCR/抓取完成；失败有可见状态；任务登记后尚未入队即退出、Redis 队列丢失、重复投递、消费者中断、限流、下载超时、识别为空与海报无匹配均可恢复或明确结束；纠错和删除竞态不丢用户修改。

### M4 — 批量、增量与 WebSocket

交付：
- 首次分页快照带一致的同步游标；新增、编辑、删除、任务结果纳入持久增量。
- WebSocket 只推必要状态和变化提示，不推图片二进制或整份票夹。
- 重连按游标补拉，过期游标重新取快照；重复和乱序通知不让状态倒退。
- 沿用按字段、服务器顺序的冲突规则，删除后旧修改不能复活；元数据编辑要求联网。
- 同账号多个页面/设备可共同使用；退出、换号、会话失效时及时取消订阅和旧请求。

验收：快照与订阅之间的变化不丢失；掉线期间发生多次更新后能够补齐；重复提交幂等；跨账号不能订阅；对比旧快照轮询的请求次数与响应字节。

### M5 — 本人设备 P2P 与中继

交付：
- 设备登记、在线心跳、媒体清单与授权信令；按当前会话核验同账号归属。
- WebRTC DataChannel 传原票和海报，直连优先、TURN 可回退；中继凭据有期限，不能成为公共转发入口。
- 比对缺失文件、分块传输、背压、取消、重连/续传与全文件哈希校验。
- 收齐并持久保存后才更新本机清单；源端失联、源文件丢失、接收空间不足分别反馈真实状态。
- 删除传播时清除记录关联，文件仅在本机无其他引用后回收。

验收：两设备直连成功；强制使用中继也成功且统计流量；中断后恢复；重复同步不重复完整下载；源端离线先显示元数据并等待，上线后补图；已知哈希不能越权下载。

### M6 — 响应式 Web 完整验收与课程证据

交付：
- 电脑、手机、平板的同一应用完成全流程，页面前台在线时支持设备同步。
- 在课程演示中展示状态、流水线和传输过程；不引入社交或新业务扩大范围。
- 同负载对比旧全量轮询与新方案；记录测试提交、环境、样本数、并发数、冷/热缓存条件与失败率。

验收：
- 自动化覆盖认证、业务闭环、任务故障、增量补拉、连接与文件校验；响应式宽度覆盖 360/390、768、1280/1440。
- 真实手机和平板浏览器由用户验收；多浏览器自动化不能冒充物理设备验收。
- 报告状态请求数/字节、缓存命中、接口 P50/P95 延迟、队列等待与处理耗时、P2P 成功率、直连/中继字节及故障恢复结果。
- 使用“同账号几百条记录”场景复现原有压力，再逐级增加并发；不预设未经测试的 QPS、节流比例或峰值容量。
- 独立审查通过、必要测试与构建通过、提交并推送后交付；发布另行等待用户明确要求。

### M7 — Web 完成后开发 Android

沿用既有 Kotlin 原生方向，在 `demo/` 之外建立工程。复用既定数据、账号与传输协议，实现电影票操作、原票/海报持久保存、实时状态和本人设备同步。不得重新引入离线 CRUD、近场朋友分享、徽章或浮雕。

先核实移动端认证、文件权限和前后台传输行为，再定义平台实现与真机验收。Android 开发不阻塞首版 Web 的完成；真机验收由用户执行。

## 4. 工程参数与风险收敛

以下是实施时需验证的参数，不是新增业务需求：

| 项目 | 实施要求 |
| --- | --- |
| 海报来源与高清阈值 | M3 用真实电影票样本确定单一来源、匹配规则和分辨率目标；无可信结果退回原票 |
| 任务与临时文件 | M3 给出超时、有限重试、临时保留期、未领取失效和重处理路径；不悄悄删除设备唯一原票 |

| 浏览器媒体存储 | M2/M6 验证各目标浏览器的容量、持久化与清理行为；不能保证永久不被系统清理 |
| 连接与传输 | M5 根据实际网络确定分块、并发、背压、续传和 TURN 配置；无可用源设备时等待 |
| 旧业务数据 | 迁移先列范围和备份，再在隔离副本验证；实际用户数据或云资源删除需明确授权 |
| 运行预算 | 并发和容量从实际可用资源测量；不因文档选型自动扩容、购买服务或改变 58 分钟关机规则 |
