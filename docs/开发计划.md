# 开发计划：个人电影票整理与多端同步

更新日期：2026-10-26。产品依据：[当前产品规格](项目定义与决策主文档.md) v0.25。

## 1. V0 状态与执行边界

Web 与 Kotlin Android 的核心功能作为 V0 基线，后续优先修复可复现问题，再做增量功能。下文 M1—M7 保留为实现范围和验收标准，不是尚未开始的任务清单，也不表示所有真实环境验收均已完成。

2026-10-24 已完成 keepsite 改名后的服务器发布，之后完成手机新包安装；用户反馈两台手机简单使用正常。账户绑定与 TMDB 已实现，允许密码邮箱与 Google 邮箱不同。真实云端绑定、完整恢复及跨网络故障矩阵仍须专项验收，详见 [V0 验证摘要](V0验证摘要.md)和 [迁移说明](keepsite迁移.md)。

- 保留原票、已保存记录和备份；缓存清理不等于业务删除。
- 每个修复验证后提交，阶段完成后独立审查并提交 PR。
- 测量与验收只证明对应提交和环境，不把模拟夹具当作生产结果。
- 部署、服务器启停和 PR 合并需用户明确授权；按 D-083 保持现有 EC2 全天运行，不自行停机。
- 当前产品规格为需求入口，本文维护迭代计划；逐轮日志从 Git 历史追溯。

## 2. 当前实现基线

现行实现包括响应式 Web、Kotlin Android、Cognito 登录与显式账户绑定、SQLite 持久票根和变更日志、私有 S3、Redis、电影票识别、海报检索、游标同步及受限 P2P。2026-10-25 用户指定用千问替换本地 OCR；本轮源码、接口联调和凭据配置分别验证，生产版本是否切换以实际发布记录为准。源码入口统一见 [README](../README.md#代码入口)，不再维护旧收藏/浮雕代码地图。

具体完成度与验证边界见 [V0 验证摘要](V0验证摘要.md)。新功能与修复须在此基线上追加验证，不沿用旧提交的通过结论。

## 3. 串行里程碑

### M1 — 收窄业务、定义数据与迁移边界

交付：
- 电影票列表、上传编辑、详情和必要设备状态的页面范围；移除分类标签、探索分享、徽章节日及浮雕入口。
- 统一票根字段、字段来源、处理状态、媒体状态、版本、删除标记与操作标识。
- 新用户空票夹；移除旧社交/模型初始模板依赖。
- 提出旧数据库与云端文件的迁移清单，保留用户原票和可恢复备份；不得因为新规格删去字段就直接删除用户文件、数据库、模型缓存或 S3 对象。
- 在隔离数据上迁移并验证；已取消功能的调用链整体退出，不保留旧 API 映射来维持两套业务。

验收：匿名门禁与双账号隔离继续有效；新账号不再产生旧模板内容；新字段和页面一致；可分别识别“尚未云存”“云存成功但尚未处理”和“本机没有缓存”。

### M2 — 持久元数据、S3 媒体、Redis 与浏览器缓存

交付：
- 数据库保存元数据、操作幂等记录和持久变更日志；Redis 保存可重建缓存、在线状态与队列。数据与变更日志同事务。
- 沿用私有 S3 保存原票和海报，记录对象键、内容哈希、归属和云端保存状态。原票上传先完成验证和持久引用提交，再确认云端保存成功。
- S3 写入与数据库提交分别可恢复：上传意图可追踪，结果未知先核对，重试不重复建记录，未被引用的对象可按策略清理；不能仅相信客户端声称已上传。
- Web 缓存可回收且按账号隔离，持久缓存写入成功不是上传前提。清除缓存、换新浏览器或没有其他在线设备时，都能在登录且服务可用后从云端恢复已保存内容。
- 定义未上传草稿、原票云存状态、任务状态、海报云存状态和本机缓存状态；上传失败时保留当前选择/草稿供重试，不能承诺草稿在清空浏览器数据后恢复。
- 保留私有桶、静态加密、HTTPS 和最小权限。评估短期授权直读；签名过期重新授权，不把临时 URL 当对象身份，不将长期凭据送到浏览器。新增权限按精确对象范围评审。
- 沿用 JPG/PNG/WebP、12 MiB 作为初始上传约束。明确缓存空间不足时的直接展示路径。
- 云端引用回收和 S3 历史版本清理分别设计，不自动清空旧桶或用户数据。建议接入访问日志、CloudTrail 数据事件及必要指标，并先核算额外费用；文档阶段不启用云资源配置。

验收：Redis 重启不丢已确认元数据；对象上传后数据库提交失败、上传响应丢失、重复确认均可核对恢复；跨账号不能获取文件；所有浏览器缓存清空后，已云存原票/海报可以恢复；未成功上传的草稿准确提示风险；缓存不足不影响云端已有数据。

### M3 — 千问视觉识别、海报与异步状态

交付：
- Redis Streams 流水线：已云存原票的任务登记、入队、千问识别、五字段校验、单一来源海报抓取、海报存入 S3、发布引用与状态、处理中间文件清理。
- 已确认任务须有数据库中的可恢复处理意图；登记后入队中断或 Redis 队列丢失时补投或明确可重处理，不能永久等待。
- 识别限定片名、影院、影厅、座位和放映时间，固定输出 `title/cinema/hall/seat/showtime` 五个字符串，未知留空，用户字段优先。放映时间无完整日期时不得猜年份。
- 按 D-082 更新 VLM 片名提示与输出校验：清理 2D/3D、中文版/英文版等完整场次后缀，保留续集序号及真实名称；海报查询复用清理函数，手工标题保持原值。
- 只接入用户指定工作空间的 `qwen3.7-flash` OpenAI 兼容接口，图片由后端临时编码传入；关闭思考及工具调用，使用 JSON 模式并严格校验字段。移除新运行链的 RapidOCR/ONNX 模型安装、启动检查与 CI 下载，不以缺模型继续阻止处理。
- 用有标注的真实/合成票面覆盖简体中文、英文字母、倾斜、低对比和模糊情况。测量字段准确率、请求与端到端耗时、API Token 用量及本机预处理内存；合成图调用成功不能替代真实票据准确率验收。
- 限制输入图、输出 Token、响应体、并发和总等待时间。每次尝试最多一次模型调用，不叠加 SDK 重试；暂态错误有限退避，鉴权、配置和无效响应等永久错误明确失败。免费额度与费用控制沿用控制台现有设置，不自动更改套餐或调用其他模型。
- 海报沿用用户 2026-10-24 确认的 TMDB 来源与署名规则；匹配不可靠时继续显示原票。
- 片名/原名精确匹配优先；只有没有精确命中才做最多 8 个候选的完整别名验证。按显式年份、观影年份上限筛选后默认选最新完整上映日期；覆盖 27 条分页、结果乱序、同年不同日期、日期并列/缺失/非法及最新作品无海报，不按排名或热度选旧作品。
- 视觉 API 与海报网络分别限制资源；修改原票或匹配字段后更新输入版本，旧任务不能覆盖。识别字段持久化后海报重试不重复识别。
- 原票已云存时识别、抓取或海报上传失败不影响原票保存。新海报云端保存并核验后才切换引用；引用发布失败可恢复，不提前删除旧有效封面。
- 客户端离线不阻塞云端任务完成，也不令已云存海报过期；临时清理仅回收中间文件、未提交或无引用产物。
- 本阶段完成第三方免费 TURN 的选型准备：固定一家官方公开提供的服务，核验注册/凭据、免费额度、是否超额计费及目标网络连通性；验证中继候选可用，形成 M5 可用的配置。优先选择有硬额度限制或明确无超额计费的免费方案；无法避免收费风险时不启用 TURN，保留 S3 路径。不搭建 coturn，不新增自管中继实例；账号管理密钥不得暴露给浏览器或提交 Git。

验收：原票保存后响应不等待模型识别；入队前退出、队列丢失、重复消费、消费者中断、下载/上传失败和无匹配均可恢复或明确结束；覆盖千问鉴权失败、限流、超时、慢流、非法/截断 JSON、用户纠错及删除竞态；旧 CPU OCR 基准保留历史定位，另交付千问接口测试、合成与真实票面验证边界，以及免费 TURN 的核验记录或明确未启用原因。

### M4 — 批量、增量与 WebSocket

交付：
- 首次分页快照带一致的同步游标；新增、编辑、删除、任务结果纳入持久增量。
- WebSocket 只推必要状态和变化提示，不推图片二进制或整份票夹。
- 重连按游标补拉，过期游标重新取快照；重复和乱序通知不让状态倒退。
- 沿用按字段、服务器顺序的冲突规则，删除后旧修改不能复活；元数据编辑要求联网。
- 同账号多个页面/设备可共同使用；退出、换号、会话失效时及时取消订阅和旧请求。

验收：快照与订阅之间的变化不丢失；掉线期间发生多次更新后能够补齐；重复提交幂等；跨账号不能订阅；对比旧快照轮询的请求次数与响应字节。

### M5 — 本人设备 P2P 加速与 S3 兜底

交付：
- 设备登记、在线心跳、缓存清单和同账号授权信令；本机有效缓存优先，缺少时在有限预算内尝试 P2P，再转授权 S3 获取。
- WebRTC DataChannel 直连，复用 M3 核验的第三方免费 TURN，不自建；没有在线源、连接失败、传输停滞或校验失败时走 S3。中继尝试同样有界，免费额度不足、服务不可用或存在超额收费风险时直接回退 S3。
- 分块、背压、取消、恢复和完整哈希校验；选定可用传输后取消多余路径，分别记录 P2P、TURN、S3 的字节和时延。
- 本机缓存写入成功才更新缓存清单；缓存失败或被清理不影响已云存文件，可重新获取或直接展示。
- P2P 与 S3 使用相同的用户归属检查；临时地址和中继凭据有有效期，过期重新授权。
- 删除先撤销后续业务授权、同步删除标记，再清本机关联和无引用缓存；对象及历史版本回收按 M2 策略执行。

验收：两设备直连与所选免费服务的强制中继均可校验；禁用 P2P、源端离线、连接超时、传输中断/校验失败、模拟免费额度不足或中继故障时从 S3 完成获取；清空全部设备缓存仍可恢复云存原票和海报；重复同步不重复完整下载；缓存不足、授权过期、S3 缺失/故障分别反馈真实状态。免费服务尚不可用时明确记录该验收未完成，不冒称通过。

### M6 — 响应式 Web 完整验收与课程证据

交付：
- 电脑、手机、平板的同一应用完成全流程，页面前台在线时支持设备同步。
- 在课程演示中展示状态、流水线和传输过程；不引入社交或新业务扩大范围。
- 同负载对比旧全量轮询与新方案；记录测试提交、环境、样本数、并发数、冷/热缓存条件与失败率。

验收：
- 自动化覆盖认证、业务闭环、任务故障、增量补拉、连接与文件校验；响应式宽度覆盖 360/390、768、1280/1440。
- 真实手机和平板浏览器由用户验收；多浏览器自动化不能冒充物理设备验收。
- 报告状态请求数/字节、缓存命中、接口 P50/P95 延迟、队列等待与处理耗时、视觉识别字段准确率/Token 用量/本机预处理内存、P2P 成功率、直连/中继/S3 请求与字节及故障恢复结果。
- 使用“同账号几百条记录”场景复现压力，对比仅 S3 与 P2P 加速，并分别测冷/热缓存，再逐级增加并发；不预设未经测试的 QPS、节流比例或峰值容量。
- 独立审查通过、必要测试与构建通过、提交并推送后交付；发布另行等待用户明确要求。

### M7 — Web 完成后开发 Android

沿用既有 Kotlin 原生方向，在 `demo/` 之外建立工程。复用既定数据、账号与传输协议，实现电影票操作、原票/海报云存与本地缓存、实时状态和本人设备加速/恢复。不得重新引入离线 CRUD、近场朋友分享、徽章或浮雕。

先核实移动端认证、文件权限和前后台传输行为，再定义平台实现与真机验收。Android 开发不阻塞首版 Web 的完成；真机验收由用户执行。

## 4. 工程参数与风险收敛

以下是实施时需验证的参数，不是新增业务需求：

| 项目 | 实施要求 |
| --- | --- |
| 海报来源与高清阈值 | M3 用真实电影票样本确定单一来源、匹配规则和分辨率目标；无可信结果退回原票 |
| 千问视觉识别 | M3 固定工作空间、模型 ID、五字段契约与预处理参数，凭据独立保密；以字段准确率、端到端耗时和实际 API Token 用量验收，不混用旧 CPU OCR 数字 |
| 任务与中间文件 | M3 给出超时、有限重试、未提交产物与中间文件保留期；原票与有效海报在 S3 长期保存，不依赖设备领取 |
| 增量窗口 | M4 定义分页量、游标保留期、失效后全量校准和删除标记保留策略 |
| 浏览器缓存与恢复 | M2/M6 验证缓存被清理、空间不足和全设备缓存丢失后的 S3 恢复；未上传草稿单独提示 |
| 连接与传输 | M3 核验一家第三方免费 TURN，M5 接入并确定分块、背压、重试和等待预算；不自建，不可用、额度不足或超时转 S3 |
| 云端媒体费用 | 统计 S3 容量、版本、请求与传出流量；P2P 不消除存储费。TURN 限免费方案/额度，存在超额收费风险时停用，不自动付费 |
| 旧业务数据 | 迁移先列范围和备份，再在隔离副本验证；实际用户数据或云资源删除需明确授权 |
| 服务可用性 | D-083 已选择现有 EC2 全天运行；持续核对服务与发布健康，不把常开视为高可用或无故障保证 |
| 运行预算 | 并发和容量从实际资源测量；不因文档选型自动扩容、购买服务或改变已授权的全天运行策略 |

M2 工程参数：Redis 快照 TTL 60 秒、单项 8 MiB，连接/读取各 0.5 秒且不自动重试；Redis 不可用回持久数据库。上传意图在对象 I/O 前登记，后台每 30 秒最多核对 3 条，自动核对窗口为创建后 24 小时；之后保留意图并支持显式查询恢复，停止后台消耗存储请求。S3 核对使用原生完整 SHA-256；直读授权为 60 秒且默认关闭，实际 CORS 与云端授权须在明确授权的环境验收中核对。Web 媒体缓存每账号上限 128 MiB，4 条并发、近视口 200 px 按需加载，离屏释放内存资源；这组初值须随 M6 测量评估。

M2 保留与回收设计：删除立即提交墓碑并停止新业务授权，已签发地址等待自身到期。原票和当前海报长期保留；上传意图与无引用产物先保留供核对，不运行自动删除。未来人工清理候选至少等待 7 天，执行前重新检查所有账号的有效引用、未完成上传/处理意图与备份需求。S3 历史版本单独审阅，30 天仅为候选审阅阈值，不是已配置的自动删除期限；普通对象删除标记不等于清空版本。本次不授予 DeleteObject/DeleteObjectVersion，不安装生命周期规则，不删除旧桶对象。实际回收需要具体授权与可核对清单，阈值的存储成本在该操作前按实有用量核算。

本轮 Android 导入参数：源文件最多 12 MiB、4000 万像素；HEIC/HEIF 依赖 Android 9（API 28）及以上设备的实际解码能力，转换前将解码目标限制为最长边 3072、最多 600 万像素，输出 JPEG 质量 90，规范化方向并使用 sRGB。转换不是无损备份，界面需说明；输出继续满足现有 12 MiB、JPEG 媒体协议。照片读取与转换合计预算 20 秒，超时或后台失效后不发布迟到结果；执行器与清理线程均须有界，不用不断新增线程掩盖不合作的数据提供方。
