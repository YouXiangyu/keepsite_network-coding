## 业务边界

- 后端：应用装配 → HTTP 适配/共享契约 → 收藏、社交、资料业务服务 → 数据库与对象存储；账户初始化、快照展示、生成调度、生成流水线、任务事务、备份恢复分别有明确入口。
- 前端：身份门禁 → 页面组装 → 账户协调 hook、业务页面与收藏草稿 → 唯一请求层。写操作、上传保存和导出共用一个锁；会话 epoch、账户 key、revision 和轮询失效规则集中维护。
- 发布：本地执行锁与唯一上传路径 → 服务器准备事务 → 激活/健康检查/恢复事务。准备与激活使用同一服务器锁。
- 文件导航见根 README、backend/README 与 demo/README；不增加兼容别名、全仓 formatter、额外状态库或多 worker 配置。

## 审查中追加修复

- 发布失败提示已出现、worker active 尚未移除时，人工恢复请求可能被吞掉；现在记录请求并由下一次调度处理。
- 回滚原先会启动用户本来停着的服务；现在保存并恢复原运行状态。
- 安装器主进程提前退出后，存活子孙可能越过部署锁；现在清理所拥有进程组后才释放锁。
- 恢复中断标记原先只作提示；现在应用与 Store 都在写入前拒绝该目录。
- 恢复校验覆盖缺字段、错误类型、跨 owner、当前任务/输入不匹配、ready 缺模型/相机、篡改或多余文件、ZIP 链接与资源上限，避免恢复出前端不能读取的账号。
- 导出流超出声明大小时在下一次写入前停止，关闭 reader 并删除半成品 ZIP，避免不受控占用磁盘。
- 同 revision 的旧轮询可能盖回刚清除的恢复提示；操作开始时取消旧轮询，锁期间不发新轮询，操作代次变化使旧响应失效。
- 新建已经落库但响应超时后修改草稿，重复 POST 会永久 409；用户确认同 ID 记录后转 PATCH，保留草稿与上传缓存，不重复创建。

## 操作边界

- 发布重试最多 3 次、总预算 8 秒；耗尽后保留同进程完成结果，用户显式重试保存。服务重启会重新排队持久 processing 任务，可能再次推理；没有宣称跨进程恰好执行一次。
- 6 秒验收针对推理子进程。已经在途的 S3 请求依靠现有连接/读取截止时间与有限 SDK 重试，取消保证不再启动后续阶段。
- 可捕获信号恢复不覆盖 SIGKILL、断电或存储硬件永久故障；此类场景按部署备份/恢复说明核对实际状态。
- 恢复工具只创建新的本地数据目录，不把资料导入生产、上传 S3 或变更 Cognito。旧 schema 1 迁移工具不用于 schema 2 账户恢复。
- 浏览器故障测试使用独立 HTTP 身份/业务夹具；真实 CPU 与恢复测试使用实际后端、SQLite、本地对象存储及测试身份。它们不替代发布后的真实 S3、Cognito 提供方、Google 同意和邮件投递验收。
- 当前仍为单进程、单生成 worker。未更改服务器 58 分钟自动关机规则。
- 测试服务与子进程已退出。自动审批以 `blocked by policy` 拒绝删除本轮 `.cache/pytest-backup-restore-20261018-a` 至 `-f` 及 `.cache/pytest-real-generation-20261018-a` 中间产物；未绕过、未声称清理成功。最终后端验证目录与浏览器截图保留供 review，先前被拒绝清理的历史目录未再触碰。
