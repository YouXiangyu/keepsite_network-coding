# MemoVerse 项目交付

更新日期：2026-10-20。

让每次完成的修改可追溯，每个应用大阶段经过独立审查与验证。部署、服务器启停和 PR 合并只在用户明确要求时执行；阶段完成、审查通过或创建 PR 都不自动触发它们。

## 开始工作

- 先读仓库 `AGENTS.md`，涉及前端时再读 `demo/AGENTS.md`。遵循其中当前的客户端运行与鉴权边界；用户明确调整平台形态时同步更新约定和验证契约，不沿用已被替代的手机模拟器要求。
- 只读检查可以直接执行；写入、下载、安装、构建、清理和部署前，先用简短说明给出范围与计划。
- 检查 Git 分支、已有改动和当前任务，区分本次修改与用户已有工作。遇到互相矛盾的指令，停止受影响步骤并澄清，继续不依赖该决定的工作。
- 使用 D 盘工作区。部署、维护服务器或更新环境信息时，读取 [项目运行信息](references/project-context.md)，操作前重新确认易变状态。

## 每个修改单元都提交 Git

- 一个完成的修改、fix 或小版本形成一个独立、含义明确的提交；先完成相关验证，再提交。这里的“每次修改”指完整逻辑单元，而非每次保存文件。
- 阶段中的后续修复、格式整理和文档修正也提交记录。默认追加提交，不用 amend、squash、强推或重置抹掉已有记录。
- 提交前检查 staged diff，排除密码、私钥、个人图片、数据库、模型产物、缓存和临时包；只纳入当前任务授权的改动。
- 若验证失败，先修复。必须保留未完成工作的情况，应明确标记 WIP 和失败原因，不能当作可部署版本。
- 本地 commit 和推送 GitHub 是两件事：完成逻辑单元即 commit；大阶段通过审查后至少推送一次，并核对远端提交。

## 应用大阶段结束：子代理审查与格式整理

“大阶段”是可单独验收的功能、成组修复或结构调整完成，不是每次聊天结束。阶段范围应在工作计划中明确。

1. 必须委派子代理审查本阶段 diff、相关调用链和项目结构，同时检查格式一致性，提出与本阶段有关的健壮性和结构改进；要求报告具体文件、问题影响和验证缺口。审查要覆盖错误处理、数据持久化、异步任务、输入边界、资源释放和访问控制中与改动相关的部分。
2. 按仓库已有格式约定整理本阶段修改。存在 formatter 时先检查再格式化对应文件；不存在时保持邻近代码风格，不为本阶段擅自引入全仓 formatter 或重排全部代码。
3. 修复阻碍正确性、健壮性和维护的问题；优先修正调用逻辑、职责边界和重复实现，避免增加兼容映射、兜底补丁或无关重构。超出本阶段的问题单独记录。
4. 不修改受保护的前端运行时来满足格式要求，不放宽锁文件或测试断言掩盖错误。
5. 对审查导致的新改动执行必要检查并提交；重要修复交回子代理复核。审查工具不可用或有未解决的关键问题时，说明原因并停在发布前，不能声称已完成独立审查。

验证依据改动选择：后端行为测试、前端测试与生产构建、`npm run check:runtime`、必要的真实生成及浏览器交互。只改技能或说明时做技能/文档校验，不无故重跑整套应用测试。

## 发布 AWS（仅在用户明确要求时）

- 只有用户明确要求部署时才发布。发布对象必须已完成阶段审查、格式整理、相关检查和 Git 提交。纯技能或说明维护无需制造一个没有运行内容变化的服务器版本。
- 优先用 AWS MCP 按运行信息中明确的 EC2 instance ID 查询实例。部署前确认实例为 `running` 且状态检查通过；若为 `stopped`，只在用户要求的发布或维护任务中启动并等待就绪。处于过渡或异常状态时先查明，不重复发启停命令，不选择账户中其他测试机。
- 启动后查询当次公网 IP，核对自动 DDNS、SSH 可达性、磁盘、服务与证书；动态公网 IP 可能变化，禁止沿用旧 IP。不要因管理端 IP 变化而默认向全球开放 SSH。
- 发布入口是 `scripts/deploy-ubuntu.ps1`：先查看计划，执行使用 `-Execute`。要求干净且已提交的工作树，上传的源码和构建必须对应同一 commit。
- 不覆盖持久数据、共享模型、环境文件、认证文件和证书。该脚本不会替你启动 EC2，也不会执行全部审查与验收。
- 相同 commit 的发布目录已存在时，先判定是已启用、已准备还是上次失败；不要盲删目录或制造无意义提交绕过检查。发布失败后核对实际 `current` 链接与服务状态，不能假定自动回滚一定完成。
- 发布后检查内部 health、HTTP→HTTPS、未认证访问拒绝、认证后的页面/API/媒体，以及本次变更的关键功能。涉及更新流程时核对数据保留。向用户交付 URL、源码 commit、实际运行 commit 和验证结果，等待用户验收。

## 用户验收与服务器启停

- “代理检查通过”和“用户确认测试没问题”是不同事件。2026-10-18 用户明确更新默认规则：每次 EC2 开机 58 分钟后自动发起正常关机，等待验收也不暂停倒计时。
- 用户要求部署或维护时按需开机，核验 `memoverse-auto-stop.timer` 已启用及本次剩余时间；不得为继续部署、生成或等待用户而自行延长或取消。用户确认测试通过或明确要求时可以提前停机，无需重复索取同一权限；代理检查通过不能代替用户确认。若需要超过 58 分钟，先取得用户对本次延长的明确授权。
- 定时器使用 `OnBootSec=58min`，应用重启/发布不重置倒计时，系统重新启动会重新计时。正常关机前应确认 EC2 的 `InstanceInitiatedShutdownBehavior=stop`；不得使用 terminate 或强制 poweroff。在第 58 分钟发起关机，为服务退出和 AWS 状态转换预留约两分钟缓冲，但不保证严格在开机后 60 分钟内进入 stopped。
- 手动提前停机前检查生成/传输是否仍在进行，按明确 instance ID 正常执行 EC2 StopInstances 并验证 `stopped`。自动定时器走服务器正常 poweroff；两条路径都应核验停机与 DNS 撤回，记录域名暂时不可访问。不要把停止 FastAPI 进程当作关闭实例，也不默认强制停机。
- 停机不等于删除。不得为了省钱自动删除实例、卷、快照、静态 IP 或域名；删除需要具体的新授权和数据处理方案。
- EC2 停机后计算费停止，但磁盘和保留的固定公网 IP 等可能继续收费。动态公网 IP 停机释放；自动 DDNS 需要核验，而不是声称关机后总费用为零。任何启停策略变化都同步更新此处和运行信息。

## 信息维护与清理

- 关键环境事实集中维护在 [项目运行信息](references/project-context.md)：域名、仓库、区域/实例、IP、部署入口、数据/模型/认证路径以及生效的启停策略。记录核验日期；运行状态与当前 commit 现场查询，不把历史记录当实时事实。
- 产品规则只更新 `docs/项目定义与决策主文档.md`（当前规格，只写有效规则与决定编号）；执行顺序与工作包更新 `docs/开发计划.md`；`docs/history/` 与 `docs/sources/` 只读，不再更新；部署证据更新既有验收记录。避免新增内容重复或互相冲突的说明。
- 完成验证后清理本任务创建的临时脚本、上传包、测试数据、临时网页和闲置进程。先确认所有权、依赖和路径边界；保留仍用于运行、重现、更新和回滚的文件。
- 判断文档过时前检查引用和替代内容；先更新或合并有效信息，再移除无引用的重复文档。历史决策与验收证据不能仅因时间较早就删除。
- 密钥、测试口令只保存在受限的本机文件或服务器配置中，技能和 Git 只记录其位置，不写明文或哈希。
- 清理、提交或发布被工具拒绝时，记录具体剩余项和原因，停止绕过尝试；不要将“已尝试”报告成“已完成”。

## 收尾回报

简要说明完成内容、commit、子代理审查与必要检查、实际部署结果、待用户验证事项、实例状态，以及尚未解决的问题或未完成清理。没有进行发布或停机时，准确说明本阶段范围，不暗示已经执行。
